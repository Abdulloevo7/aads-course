## Цель работы

Реализовать три эффективных алгоритма сортировки: быструю сортировку, сортировку слиянием и пирамидальную сортировку. Освоить принцип «разделяй и властвуй» и структуру данных «куча». Сравнить три варианта выбора опорного элемента в быстрой сортировке и проанализировать производительность всех алгоритмов на данных разного размера и порядка.

## Теоретическая часть

**Разделяй и властвуй** — принцип, при котором задача делится на подзадачи меньшего размера, подзадачи решаются независимо, а их решения объединяются. Быстрая сортировка и сортировка слиянием строятся на этом принципе рекурсивно.

**Быстрая сортировка** выбирает опорный элемент, разделяет массив так, что слева оказываются элементы не больше опорного, а справа большие, и рекурсивно сортирует обе части. Работа выполняется на этапе разделения, а объединять части не нужно. Скорость сильно зависит от выбора опорного элемента: при удачном выборе части получаются равными и глубина рекурсии равна log n, при неудачном одна часть почти пуста и сложность становится квадратичной.

**Стратегии выбора опорного элемента:**

| Стратегия | Преимущества | Недостатки |
|---|---|---|
| Последний элемент | Простота | Квадратичное время на отсортированных данных |
| Медиана из трёх | Хорошо работает на упорядоченных данных | Чуть сложнее |
| Случайный элемент | Защита от худшего случая | Требует генерации случайных чисел |

**Сортировка слиянием** делит массив пополам, рекурсивно сортирует половины и сливает две отсортированные части в одну. Слияние идёт за линейное время, а глубина рекурсии равна log n, поэтому время всегда O(n log n). Для слияния нужна дополнительная память, пропорциональная размеру массива.

**Пирамидальная сортировка** строит из массива двоичную кучу max-heap, в которой каждый родитель не меньше потомков. Затем корень, то есть максимум, обменивается с последним элементом кучи, размер кучи уменьшается на единицу, и свойство кучи восстанавливается операцией `heapify`. Потомки элемента с индексом `i` лежат в позициях `2i+1` и `2i+2`.

Сравнение алгоритмов:

| Алгоритм | Лучший случай | Средний случай | Худший случай | Память | Устойчивость |
|---|---|---|---|---|---|
| Быстрая | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет |
| Слиянием | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |
| Пирамидальная | O(n log n) | O(n log n) | O(n log n) | O(1) | Нет |

// Быстрая сортировка с тремя стратегиями выбора опорного элемента
enum PivotStrategy { LAST, MEDIAN, RANDOM };

void choosePivot(int arr[], int low, int high, PivotStrategy strategy) {
    if (strategy == RANDOM) {
        int index = low + rand() % (high - low + 1);
        swap(arr[index], arr[high]);
    } else if (strategy == MEDIAN) {
        int mid = low + (high - low) / 2;
        if (arr[low] > arr[mid]) {
            swap(arr[low], arr[mid]);
        }
        if (arr[low] > arr[high]) {
            swap(arr[low], arr[high]);
        }
        if (arr[mid] > arr[high]) {
            swap(arr[mid], arr[high]);
        }
        swap(arr[mid], arr[high]);
    }
}

int partition(int arr[], int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(arr[i], arr[j]);
        }
    }
    swap(arr[i + 1], arr[high]);
    return i + 1;
}

void quickSort(int arr[], int low, int high, PivotStrategy strategy) {
    if (low < high) {
        choosePivot(arr, low, high, strategy);
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1, strategy);
        quickSort(arr, pi + 1, high, strategy);
    }
}
```

// Сортировка слиянием
void merge(int arr[], int left, int mid, int right) {
    int n1 = mid - left + 1;
    int n2 = right - mid;
    int* L = new int[n1];
    int* R = new int[n2];

    for (int i = 0; i < n1; i++) {
        L[i] = arr[left + i];
    }
    for (int j = 0; j < n2; j++) {
        R[j] = arr[mid + 1 + j];
    }

    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) {
            arr[k++] = L[i++];
        } else {
            arr[k++] = R[j++];
        }
    }
    while (i < n1) {
        arr[k++] = L[i++];
    }
    while (j < n2) {
        arr[k++] = R[j++];
    }

    delete[] L;
    delete[] R;
}

void mergeSort(int arr[], int left, int right) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }
}

// Пирамидальная сортировка
void heapify(int arr[], int n, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest]) {
        largest = left;
    }
    if (right < n && arr[right] > arr[largest]) {
        largest = right;
    }
    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void heapSort(int arr[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--) {
        heapify(arr, n, i);
    }
    for (int i = n - 1; i > 0; i--) {
        swap(arr[0], arr[i]);
        heapify(arr, i, 0);
    }
}
```

    int reps = 100000 / n;
    if (reps < 1) {
        reps = 1;
    }
    int* buf = new int[(long long)reps * n];
    for (int r = 0; r < reps; r++) {
        for (int i = 0; i < n; i++) {
            buf[(long long)r * n + i] = src[i];
        }
    }
    auto start = high_resolution_clock::now();
    for (int r = 0; r < reps; r++) {
        sortFunc(buf + (long long)r * n, n);
    }
    auto end = high_resolution_clock::now();
    ok = true;
    for (int r = 0; r < reps; r++) {
        if (!isSorted(buf + (long long)r * n, n)) {
            ok = false;
        }
    }
    delete[] buf;
    return duration<double, micro>(end - start).count() / reps;
}

| Быстрая | O(n log n) | O(n log n) | O(n²) | O(log n), в худшем случае O(n) | Разделение за O(n) на каждом из log n уровней. Если опорный всегда крайний, уровней становится n, а глубина рекурсии растёт до n |
| Слиянием | O(n log n) | O(n log n) | O(n log n) | O(n) | Всегда ровно log n уровней и слияние за O(n) на каждом, не зависит от данных |

Рекурсивный `heapify` использует стек глубиной до log n, поэтому в нашей реализации дополнительная память равна O(log n), а при замене рекурсии на цикл становится O(1).

## Ответы на контрольные вопросы

**1. Какова сложность быстрой сортировки в лучшем, среднем и худшем случае?**

В лучшем и среднем случаях O(n log n), в худшем O(n²). Лучший случай возникает, когда опорный элемент делит массив примерно пополам, и глубина рекурсии равна log n.

**2. Когда возникает худший случай для быстрой сортировки?**

Когда опорный элемент оказывается минимальным или максимальным в своей части, и массив делится на пустую часть и часть из n − 1 элементов. Для опорного последнего или первого элемента это происходит на уже отсортированных и обратно отсортированных данных. В эксперименте на отсортированных данных сортировка заняла 30 874 мкс против 491 мкс на случайных.

**3. Как можно улучшить быструю сортировку для защиты от худшего случая?**

Выбирать опорный элемент случайно или как медиану из трёх, то есть из первого, среднего и последнего элементов. Можно использовать трёхчастное разделение для массивов с повторами и переходить на пирамидальную сортировку при слишком большой глубине рекурсии, как в интроспективной сортировке. Для коротких подмассивов выгодно переключаться на сортировку вставками.

**4. Какова сложность сортировки слиянием? Почему она всегда O(n log n)?**

O(n log n) во всех случаях. Массив всегда делится ровно пополам, поэтому уровней рекурсии log₂n, а слияние на каждом уровне обрабатывает все n элементов за линейное время. Данные на количество уровней не влияют.

**5. Какие преимущества и недостатки имеет сортировка слиянием перед быстрой?**

Преимущества: гарантированное время O(n log n), устойчивость, хорошая работа со связными списками и внешними файлами. Недостатки: нужна дополнительная память O(n), а копирование данных замедляет работу на массивах в памяти. В эксперименте слияние было самым медленным из трёх алгоритмов на случайных данных.

**6. Как работает пирамидальная сортировка? Какова её сложность?**

Из массива строится max-heap. Затем корень, то есть максимальный элемент, меняется местами с последним элементом кучи, размер кучи уменьшается, и свойство кучи восстанавливается операцией `heapify` для нового корня. Построение кучи занимает O(n), а n извлечений по O(log n) дают общую сложность O(n log n) во всех случаях.

**7. Какая из трёх сортировок устойчивая? Почему?**

Только сортировка слиянием. При слиянии условие `L[i] <= R[j]` берёт элемент из левой половины при равенстве, поэтому порядок равных элементов сохраняется. Быстрая сортировка неустойчива из-за обменов элементов на большом расстоянии при разделении. Пирамидальная неустойчива, потому что обмен корня с последним элементом нарушает относительный порядок.

**8. Какая из трёх сортировок требует дополнительной памяти? Сколько?**

Слиянием требует O(n) для временных массивов. Быстрой нужен стек рекурсии глубиной в среднем O(log n), в худшем случае O(n). Пирамидальная сортирует на месте и требует O(1) при итеративном `heapify`, а в нашей рекурсивной версии стек до O(log n).

**9. Какая из трёх сортировок лучше работает на почти отсортированных данных?**

В эксперименте на почти отсортированных данных лучшим вариантом оказалась быстрая сортировка с медианой из трёх, 243 мкс. Следом идут пирамидальная сортировка с 333 мкс, быстрая со случайным опорным с 366 мкс и слияние с 467 мкс. Быстрая сортировка с последним опорным показала 793 мкс, то есть была хуже остальных, а на полностью упорядоченных данных деградирует до квадратичного времени. Слияние и пирамидальная сортировка от порядка данных почти не зависят.

**10. Зачем в пирамидальной сортировке сначала строится куча?**

Куча гарантирует, что максимальный элемент находится в корне, то есть в позиции 0, и его можно извлечь за O(1). После обмена корня с последним элементом остаётся восстановить свойство кучи за O(log n). Без кучи поиск максимума на каждом шаге стоил бы O(n) и сортировка стала бы квадратичной.

**11. Что такое «разделяй и властвуй»? Как он применяется в быстрой сортировке и сортировке слиянием?**

Это приём, при котором задача делится на подзадачи меньшего размера, подзадачи решаются независимо, а результаты объединяются. В быстрой сортировке основная работа происходит при делении, когда массив разбивается относительно опорного элемента, а объединять нечего. В сортировке слиянием деление тривиально, пополам, а основная работа происходит при слиянии отсортированных половин.

**12. Можно ли реализовать быструю сортировку итеративно, без рекурсии?**

Да. Рекурсию заменяют явным стеком, в который кладут границы подмассивов, ещё не обработанных. На каждой итерации из стека берётся пара границ, выполняется разделение, и границы двух получившихся частей кладутся обратно. Чтобы стек оставался небольшим, первой обрабатывают меньшую часть.

**13. Почему быстрая сортировка обычно быстрее сортировки слиянием на практике?**

Быстрая сортировка работает на месте, не выделяет временных массивов и последовательно обращается к памяти, что хорошо использует кэш процессора. Сортировка слиянием копирует данные и выделяет память на каждом слиянии. Это подтверждается экспериментом: на размерах от 10 000 элементов слияние оказалось примерно в 1,9–2 раза медленнее быстрой сортировки, а на малых размерах отставание ещё больше.

**14. Когда выгодно использовать пирамидальную сортировку?**

Когда важна гарантия времени O(n log n) в худшем случае и нельзя тратить дополнительную память, например во встроенных системах и в ядрах операционных систем. Она также используется как запасной вариант в интроспективной сортировке, если быстрая сортировка вырождается.

**15. Какой алгоритм сортировки вы бы выбрали для встроенных систем с ограниченной памятью?**

Пирамидальную сортировку. Она сортирует на месте с памятью O(1) для итеративной версии и гарантирует O(n log n) без худшего случая. Сортировка слиянием требует O(n) памяти, а быстрая в худшем случае переполняет стек рекурсии. Для очень малых массивов подойдёт и сортировка вставками.

## Вывод

В ходе лабораторной работы реализованы быстрая сортировка с тремя вариантами выбора опорного элемента, сортировка слиянием и пирамидальная сортировка. Корректность проверена на граничных случаях и на 1505 случайных массивах без ошибок, а память проверена инструментами контроля, утечек нет. Эксперимент подтвердил теорию: быстрая сортировка с последним опорным элементом деградирует до квадратичного времени на упорядоченных данных, примерно в 60 раз медленнее, а медиана из трёх и случайный опорный элемент эту проблему устраняют. Слияние и пирамидальная сортировка не зависят от порядка данных. На случайных данных пирамидальная сортировка и быстрая сортировка показали близкое время, а слияние было медленнее из-за выделения памяти на каждом слиянии. Различия между алгоритмами зависят от реализации, поэтому выбор сортировки определяется требованиями задачи: гарантия времени, устойчивость или ограничение по памяти.
