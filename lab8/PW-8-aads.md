## Теоретическая часть

**Двоичный поиск** находит элемент в отсортированном массиве. На каждом шаге берётся средний элемент интервала и сравнивается с искомым значением. Если они равны, поиск завершён. Если средний элемент меньше искомого, поиск продолжается в правой половине, иначе в левой. Интервал сокращается вдвое на каждом шаге, поэтому сложность O(log n), а лучший случай O(1). Итеративная версия использует O(1) памяти, рекурсивная O(log n) на стек вызовов. Середину вычисляют как `left + (right - left) / 2`, потому что сумма `left + right` может переполнить тип `int`.

**Хеш-таблица** реализует ассоциативный массив и выполняет вставку, поиск и удаление в среднем за O(1). Она состоит из массива корзин и хеш-функции, которая по ключу вычисляет индекс корзины.

**Требования к хеш-функции:** детерминированность, то есть один ключ даёт один хеш, равномерное распределение ключей по корзинам и быстрое вычисление.

**Коллизия** возникает, когда разные ключи дают одинаковый индекс. Основные способы разрешения:

| Метод | Идея | Особенности |
|---|---|---|
| Цепочки | Элементы одной корзины хранятся в связном списке | Нужна память под указатели, нет кластеризации, таблица может быть заполнена сверх размера |
| Линейное пробирование | При занятой ячейке проверяется следующая, индекс `(hash + i) % size` | Только массив, первичная кластеризация |
| Квадратичное пробирование | Шаг растёт квадратично, `(hash + i²) % size` | Меньше кластеризации, вторичная кластеризация |
| Двойное хеширование | Шаг задаёт вторая хеш-функция | Лучшее распределение, сложнее реализация |

**Коэффициент загрузки** равен отношению числа элементов к числу корзин. Он определяет среднюю длину цепочки и вероятность коллизий. Когда загрузка превышает порог, таблицу расширяют и пересчитывают позиции всех элементов. Эта операция называется **рехешированием**.

**Удаление при открытой адресации** нельзя делать простым освобождением ячейки, иначе разорвётся цепочка проб для других ключей. Поэтому ячейка помечается специальным значением «удалена».

```cpp
// Двоичный поиск
int binarySearch(const int arr[], int n, int target) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) {
            return mid;
        }
        if (arr[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }
    return -1;
}

int binarySearchRecursive(const int arr[], int left, int right, int target) {
    if (left > right) {
        return -1;
    }
    int mid = left + (right - left) / 2;
    if (arr[mid] == target) {
        return mid;
    }
    if (arr[mid] < target) {
        return binarySearchRecursive(arr, mid + 1, right, target);
    }
    return binarySearchRecursive(arr, left, mid - 1, target);
}
```

```cpp
class HashTableChaining {
private:
    struct Node {
        int key;
        int value;
        Node* next;

        Node(int k, int v) : key(k), value(v), next(nullptr) {}
    };

    Node** table;
    int size;
    int count;
    bool simpleHash;
    bool autoRehash;

    int hash(int key) const {
        return simpleHash ? hashSimple(key, size) : hashMixed(key, size);
    }

public:
    ~HashTableChaining() {
        for (int i = 0; i < size; i++) {
            Node* current = table[i];
            while (current != nullptr) {
                Node* temp = current;
                current = current->next;
                delete temp;
            }
        }
        delete[] table;
    }
};
```

```cpp
        int index = hash(key);

                current->value = value;

    bool remove(int key) {
        int index = hash(key);
        Node* current = table[index];
        Node* prev = nullptr;
        while (current != nullptr) {
            if (current->key == key) {
                if (prev == nullptr) {
                    table[index] = current->next;
                } else {
                    prev->next = current->next;
                }
                delete current;
                count--;
                return true;
            }
            prev = current;
            current = current->next;
        }
        return false;
    }
```

## Анализ сложности

| Операция | Средний случай | Худший случай | Память | Обоснование |
|---|---|---|---|---|
| Двоичный поиск, итеративно | O(log n) | O(log n) | O(1) | Интервал делится пополам на каждом шаге |
| Двоичный поиск, рекурсивно | O(log n) | O(log n) | O(log n) | Глубина рекурсии равна log n |
| Цепочки, вставка | O(1) | O(n) | O(n) | При равномерном хешировании цепочка короткая, в худшем все ключи в одной корзине |
| Цепочки, поиск | O(1) | O(n) | | Проход по цепочке длиной в среднем равной коэффициенту загрузки |
| Цепочки, удаление | O(1) | O(n) | | Поиск в цепочке и перестановка одного указателя |
| Рехеширование | O(n) | O(n) | O(n) | Перенос всех узлов, амортизированно O(1) на вставку |
| Открытая адресация, вставка, поиск, удаление | O(1) при загрузке не выше 0,5 | O(n) | O(n) | Длина пробной последовательности растёт при росте загрузки |

## Ответы на контрольные вопросы

**1. Какое условие необходимо для применения двоичного поиска?**

Массив должен быть отсортирован, и должен быть доступ к любому элементу по индексу за O(1). Без сортировки решение о том, в какой половине продолжать поиск, невозможно принять.

**2. Какова сложность двоичного поиска? Почему она логарифмическая?**

O(log n). На каждом шаге интервал поиска сокращается вдвое, поэтому после k шагов остаётся n/2ᵏ элементов, и поиск заканчивается, когда останется один, то есть при k порядка log₂n. Для миллиона элементов достаточно около 20 сравнений.

**3. В чём разница между итеративной и рекурсивной реализацией двоичного поиска?**

Алгоритм один, но итеративная версия использует цикл и O(1) памяти, а рекурсивная вызывает сама себя и расходует O(log n) памяти на стек. Рекурсивная версия короче и ближе к определению, итеративная быстрее и не имеет риска переполнения стека. Эта рекурсия хвостовая, поэтому её легко заменить циклом.

**4. Чем опасен вариант `mid = (left + right) / 2`? Как правильно вычислять середину?**

Сумма `left + right` может превысить максимальное значение типа `int`, и произойдёт переполнение с отрицательным результатом, а значит неверным индексом. Правильно писать `mid = left + (right - left) / 2`, потому что разность не превосходит `right` и переполнения не вызывает.

**5. Что такое хеш-таблица? Из каких компонентов она состоит?**

Это структура данных, которая хранит пары «ключ — значение» и выполняет вставку, поиск и удаление в среднем за O(1). Она состоит из массива корзин, хеш-функции, преобразующей ключ в индекс, и механизма разрешения коллизий.

**6. Какие требования предъявляются к хеш-функции?**

Детерминированность, то есть равные ключи всегда дают равные хеши. Равномерное распределение, чтобы корзины заполнялись равномерно. Быстрое вычисление. Как показал эксперимент, функция `key % size` на ключах, кратных размеру, отправляет все ключи в одну корзину и даёт цепочку длиной 500, а перемешивающая функция даёт максимум 4.

**7. Что такое коллизия в хеш-таблице? Как с ней бороться?**

Коллизия возникает, когда разные ключи дают один индекс. Неизбежна, так как число возможных ключей больше числа корзин. Способы борьбы: метод цепочек, где элементы одной корзины хранятся в списке, и открытая адресация, где ищется другая свободная ячейка линейным, квадратичным пробированием или двойным хешированием.

**8. В чём отличие метода цепочек от открытой адресации?**

Цепочки хранят коллизионные элементы в связных списках вне массива, поэтому нужна дополнительная память на указатели, но загрузка может превышать единицу, а удаление простое. Открытая адресация хранит всё в одном массиве, экономнее по памяти и лучше использует кэш, но требует загрузки меньше единицы, страдает от кластеризации, а удаление требует специальной пометки.

**9. Что такое первичная и вторичная кластеризация?**

Первичная кластеризация характерна для линейного пробирования: занятые ячейки образуют длинные непрерывные участки, и новые ключи, попадая в такой участок, удлиняют его ещё сильнее. Вторичная кластеризация характерна для квадратичного пробирования: ключи с одинаковым начальным хешем проходят одну и ту же последовательность проб, хотя разные начальные хеши уже не сливаются в общие участки.

**10. Какова средняя и худшая сложность операций в хеш-таблице?**

В среднем O(1), в худшем O(n), когда все ключи попадают в одну корзину или в одну пробную последовательность. Для вставки с расширением учитывается ещё и стоимость рехеширования O(n), которая в сумме даёт амортизированное O(1).

**11. Когда эффективнее использовать двоичный поиск, а когда хеш-таблицу?**

Хеш-таблица быстрее при поиске по точному ключу, в эксперименте в 5–8 раз. Двоичный поиск лучше, если данные уже отсортированы и нужны порядок, диапазонные запросы, ближайшие значения, минимум и максимум, а также если экономится память и не нужна дополнительная структура. Хеш-таблица не хранит порядок и требует память сверх самих данных.

**12. Что такое коэффициент загрузки хеш-таблицы? Почему он важен?**

Это отношение числа элементов к числу корзин. Он определяет среднюю длину цепочки в методе цепочек и вероятность коллизий. При росте загрузки операции замедляются, а в открытой адресации при загрузке около единицы поиск вырождается в линейный. Поэтому при превышении порога, например 0,75 для цепочек, таблицу расширяют.

**13. Как работает рехеширование?**

Когда загрузка превышает порог, выделяется новый массив большего размера, обычно вдвое, и все элементы переносятся в него с пересчётом индекса по новому размеру, потому что индекс зависит от размера таблицы. Старый массив освобождается. Операция занимает O(n), но случается редко, поэтому вставка остаётся амортизированно O(1). В реализации цепочек узлы не копируются, а перевешиваются на новые места.

**14. Как выбрать размер хеш-таблицы? Почему часто выбирают простое число?**

Размер выбирают так, чтобы коэффициент загрузки оставался умеренным, и расширяют при росте. Простое число используют, потому что при остатке от деления на составное число ключи с общими делителями, например кратные размеру или его делителю, попадают в малое число корзин. Простой размер разрушает такие закономерности. В работе при рехешировании размер всегда становится простым числом.

**15. Как реализовать хеш-функцию для строк?**

Обычно используют полиномиальную функцию: для каждого символа хеш умножается на константу, например 31, и прибавляется код символа, `hash = hash * 31 + c`, затем результат берётся по модулю размера таблицы. Вычисление идёт за O(длина строки). Для защиты от переполнения хеш хранят в беззнаковом типе или берут остаток на каждом шаге.

Реализованы две хеш-таблицы: с методом цепочек и с открытой адресацией и линейным пробированием, обе с динамическим расширением и рехешированием, а память проверена инструментами контроля, утечек нет.
